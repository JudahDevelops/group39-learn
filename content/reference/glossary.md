# Glossary

| Term | Meaning |
|---|---|
| Abstract | A paper's summary at the top. Ours is blank, as the lecturer asked. |
| API | The set of addresses (endpoints) the frontend uses to ask the backend for things |
| APA 7 | The citation style the lecturer requires, 7th edition |
| Artefact | In DSR, the thing you build: here, the IHMS |
| Audit log | A record of who did what and when; here, `complaint_history` |
| Backend | The server side: rules, data, emails |
| bcrypt | A slow, salted way of hashing passwords |
| Branch | A separate line of work in Git |
| Commit | A saved snapshot of changes in Git |
| Consensus | An AI search engine for academic papers |
| Constraint | A rule the database enforces on every write |
| CSS | The language for how a page looks |
| CSV | A spreadsheet saved as plain text, values separated by commas |
| DHMS | Digital Hostel Management System, a system in one of the reviewed papers (Heda et al., 2025) |
| DOI | Digital Object Identifier, a paper's permanent ID |
| DOM | The browser's object version of the page, which JavaScript can change |
| DSR | Design Science Research: building and evaluating an artefact to solve a practical problem |
| Endpoint | One address on the server, such as `/api/complaints` |
| Escalation | Alerting someone more senior when a deadline passes |
| FastAPI | The Python framework for our backend |
| Foreign key | A column that points to a row in another table |
| Frontend | What the user sees in the browser |
| Hash | A scrambled value that can't be turned back into the original |
| HTML | The language for the structure and content of a page |
| HTTP | The language browsers and servers use to talk |
| JavaScript | The language that makes pages do things |
| JSON | A text format for exchanging data |
| JWT | JSON Web Token: a signed token saying who is logged in |
| MERN | MongoDB, Express, React, Node.js, a JavaScript stack some reviewed systems use |
| Migration | A controlled change to a database's structure |
| Peer review | Checking of a paper by other experts before it's published |
| PostgreSQL | Our relational database |
| Preprint | A paper shared before peer review, for example on arXiv |
| Primary key | The column that uniquely identifies each row |
| Pull request | A request to merge a branch, reviewed by others |
| Pydantic | The library FastAPI uses to check data |
| RBAC | Role-based access control: what you can do depends on your role |
| REST | A common way of designing APIs around resources and HTTP methods |
| Scheduler | Code that runs a task on a timer |
| SJR | SCImago Journal Rank, a measure of a journal's standing |
| SMTP | The protocol for sending email |
| SQL | The language for working with relational databases |
| SQLAlchemy | The Python library we use to talk to PostgreSQL |
| Tier | One layer of the architecture with one job |
| Token | See JWT |
| Triage | Sorting by type and urgency |
| Virtual environment | A project's own private set of Python libraries |
