# --screen-- concept

A **research question** is the question a literature search tries to answer. A literature search looks for what published papers already say about your topic.

The lecturer's standard: exactly three questions, each *simple, clear and directly related to your project scope*. Expect to be asked why ours are worded the way they are.

# --screen-- mcq

## --question--

How many research questions does the lecturer require?

## --options--

- [ ] One
  > No. The lecturer's standard is three.
- [x] Exactly three
  > Yes. Three questions, each simple, clear and directly related to the project scope.
- [ ] As many as you need
  > No. The number is fixed. More questions would break the lecturer's standard.

## --why--

The standard is exactly three research questions. Each one must be simple, clear and directly related to the project scope.

# --screen-- concept

The better versions, for the same attendance topic:

- *Is attendance important?* becomes: How have computerised systems been used to record student attendance in universities?
- *How can AI revolutionise education?* becomes: What automated features can identify students at risk of falling below attendance thresholds?
- *What's the best fingerprint scanner?* becomes: What methods have been used to record and verify lecture attendance?

# --screen-- mcq

## --question--

Which question is in scope for a software project?

## --options--

- [ ] What building materials last longest in hostels?
  > No. That is about buildings, and software can't fix buildings.
- [x] What methods have been used to record hostel complaints?
  > Yes. Software can record complaints, and a literature search can find the methods already used.
- [ ] How should hostel fees be priced?
  > No. Pricing is a funding decision, and software can't fix funding.

## --why--

A research question in scope is one that software can help with and that published papers can answer.

# --screen-- concept

The group's first two questions:

| # | Focus | Question |
|---|---|---|
| RQ1 | The domain | How can a computerised system be applied to manage student hostel accommodation in universities? |
| RQ2 | Current methods | What methods have been used to allocate hostel rooms and to record hostel occupancy and complaints? |

# --screen-- concept

**RQ3, improvement.** What intelligent features can improve room allocation, maintenance handling and reporting in hostel management systems?

RQ3 was kept broad on purpose. It let the gap analysis (Lesson 1.7) decide the value-add, instead of the group picking a feature first and looking for papers to justify it.

# --screen-- mcq

## --question--

Why was RQ3 kept broad?

## --options--

- [ ] To get more papers
  > No. Breadth was not about the number of papers. It kept the feature open until the gap analysis had run.
- [x] So the gap analysis, not a guess, would decide the value-add
  > Yes. The group did not pick a feature first and then look for papers to justify it.
- [ ] The lecturer requires broad questions
  > No. His standard is simple, clear and directly related to the project scope. Keeping RQ3 broad was the group's choice.

## --why--

A broad RQ3 left the choice of feature to the evidence. The gap analysis in Lesson 1.7 made the choice.
